# FBNeo Core Specifications

Technical reference for the FinalBurn Neo core as wrapped by this repository.

This document summarizes:
- How ROM sets and BIOS files are supplied to the core
- What is currently exposed by this TypeScript WASM wrapper
- Notable upstream capabilities not yet mapped to typed SDK options

## Source of truth

Upstream FBNeo: <https://github.com/finalburnneo/FBNeo>. The SDL2 burner
(`src/burner/sdl/`) is the target compiled to WebAssembly by
`scripts/build-fbneo.sh`.

## ROM identity & assets

FBNeo identifies a game by the ROM **zip filename** (without extension) — the
"driver" / ROM-set short name (e.g. `mslug`, `sf2`, `kof98`). The host supplies:

| Asset key | Mount path | Required | Notes |
|-----------|------------|----------|-------|
| `rom` | `/roms/<romFileName>` | yes | The arcade ROM set zip. |
| `bios` | `/roms/neogeo.zip` | no | System BIOS for sets that need it (Neo Geo, CPS-3, …). |

The SDK writes these into Emscripten MEMFS before boot and launches FBNeo with
the driver short name resolved from `options.driver` or the rom filename. The
bytes are always written as `<driver>.zip`, so the source file never needs
renaming — only the *name* has to resolve to a driver.

When the filename is unreliable, the driver can be recovered from the zip's
contents: the opt-in `@wasm-gaming/fbneo-wasm/romset` helper (`src/romset.ts`)
reads each entry's CRC-32 from the zip central directory and matches it against
`data/romsets/<system>.json`. That dataset is generated by
`scripts/gen-romset-index.mjs` from FBNeo's `BurnRomInfo` driver tables (`make
romsets`), so it stays in lockstep with the compiled core's ROM identity.

Systems listed in that script's `LAYOUT_SYSTEMS` (currently `neogeo`) also record
each ROM's size (`s`) and hardware region (`r`), describing the *chip layout* of a
set rather than just its identity. Layout rows include undumped chips (CRC
`00000000`), which the layout needs to keep chip boundaries aligned but which
`RomsetIndex.rank()` excludes from identity scoring, since nothing can match them.

Inside the archive, FBNeo looks each chip up by CRC-32 first and only falls back
to filenames (`src/burner/sdl/bzip.cpp`, `FindRom`), so entry names, added files,
and subdirectories inside the zip are irrelevant — the archive just has to *be* a
zip/7z named after the driver.

Container formats other than zip/7z are not supported by the core. Neo Geo `.neo`
files (NeoSD/Terraonion flash carts) carry the same ROM data in one blob per
region; the opt-in `@wasm-gaming/fbneo-wasm/neo` helper (`src/neo.ts`) rebuilds
the chip split FBNeo expects — de-interleaving the C region, undoing the
`HARDWARE_SNK_SWAPP` program-ROM swap — and CRC-32 verifies every carved chip
against the driver tables before returning a `<driver>.zip` to mount as
`assets.rom`. It runs in the browser off the layout dataset above;
`scripts/neo2romset.mjs` is a CLI over the same code.

The zip it produces stores its entries uncompressed (method 0). FBNeo decompresses
each chip into its ROM buffer immediately, so deflating would only be undone a
moment later — storing keeps the conversion synchronous (no `CompressionStream`)
at the cost of transient memory roughly equal to the `.neo` itself.

## Wrapper exposure status (this package)

The SDK implements engine-specs 1.0 (`FbneoSDK` / `FbneoPlay`); payloads in
`src/fbneo.options.ts` (`FBNEO_SPEC`):

- config: `renderFilter` (live), `jsUrl`, `wasmUrl`;
- options: `driver`, `romFileName` (its stem is the driver when `driver` is empty);
- assets: `rom` (zip/7z), `bios` (zip);
- storage: `namespace`, `persist` → OPFS `fbneo/<namespace>/`.

What reaches the core, through `scripts/web_bridge.cpp` (appended to the SDL burner):

- `pause(owner)` / `resume(owner)` → `web_set_paused`: the patched loop skips
  `RunIdle()` (no frame emulated) and the sound stops. The burner's own `bRunPause`
  is not used: `RunIdle()` still emulates a frame with it.
- `restart()` → `web_reset`: the burner's reset (a pressed F3).
- `flushSaves()` → `web_persist`: `StatedAuto(1)`, NVRAM/EEPROM to `/save/<driver>.fs`.
- `states.save/load(slot)` → `web_save_state` / `web_load_state`: `BurnStateSave/Load`
  of `/save/slot_N.fs`.
- `start()` waits for `web_running` (the set loaded) or FBNeo's "error loading" line.
- `destroy()` → `web_quit`: the loop ends and FBNeo exits the game its own way.
