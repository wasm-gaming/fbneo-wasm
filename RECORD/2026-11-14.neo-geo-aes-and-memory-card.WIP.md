# Neo Geo as the AES: BIOS mode and memory card

2026-11-14 · for the launcher's Neo Geo (jgermade/play.germade `RECORD/2026-11-14.neo-geo-on-fbneo.WIP.md`).
Owner: "Neo Geo la tratamos como consola doméstica"; recommendations accepted ("Me valen las
recomendaciones"): accept both BIOSes and prefer the real AES one; region AES World; memory card
in the first version. Follows `2026-11-13.contract-1.0-standalone-and-engine-app.WIP.md` (0.2.0).

## Found (FBNeo @ `d7179fef`)
- Neo Geo sets boot as **MVS**. The driver's "BIOS" setting (a fake DIP, group "BIOS") picks the 68K
  BIOS, loaded **on every reset** (`neogeoReset` → `NeoLoad68KBIOS(NeoSystem & 0x3f)`); *AES World*
  (`neo-epo.bin`, CRC d27a71f1) or *Universe BIOS (Hack, Ver. 4.0)* (`uni-bios_4_0.rom`, a7aab458)
  + its "Unibios mode" setting = *AES* make the driver run as `NEO_SYS_AES` (`AES_BIOS`).
- The owner's `neogeo.zip` (MAME 0.251) has UniBIOS 4.0, not the AES BIOS.
- Memory card: the core exposes the card through `BurnAreaScan(ACB_MEMCARD)` (`NeoMemoryCard`,
  0x20000 bytes); insertion is `ACB_WRITE|ACB_MEMCARD|ACB_MEMCARD_ACTION`. Only FBNeo's Windows
  front end drives it; the SDL burner (this build) never inserts a card.

## Changes
1. **Bridge** (`scripts/web_bridge.cpp`):
   - `web_set_dip(group, option)` — set a DIP setting by the names the driver gives them (the
     same write the SDL front end's DIP menu does); 1 when found.
   - `web_memcard_insert()` — insert a card: `/save/<driver>.card` if there is one (raw, the core's
     0x20000 bytes), else a blank one; `web_persist()` also writes the inserted card back to that
     file (a plain `ACB_READ|ACB_MEMCARD` scan, no eject).
   Exported; FBNeo's sources are not patched for this.
2. **SDK**: option `neogeo: 'mvs' | 'aes'` (default `'mvs'`, as 0.2.0). With `'aes'`, once the set
   runs: the BIOS is chosen from the `bios` asset's CRCs — `AES World` if it has `neo-epo.bin`, else
   UniBIOS 4.0 + "Unibios mode" = AES, else `start()` fails with a clear message — then the card is
   inserted and the machine reset so it boots the chosen BIOS. `play.neogeo` reports what was used
   (`{ mode, bios }`). Sets that aren't Neo Geo ignore the option.
3. **App**: passes `options.neogeo` from the host (`host.options?.neogeo`), unchanged otherwise.
4. Tests (BIOS choice from a zip's CRCs), README, release **minor** → 0.3.0.

## Verify
Chromium with the owner's `mslug.zip` + `neogeo.zip` (UniBIOS path): boots in AES mode (UniBIOS
screen in AES mode, no credits); the card is inserted and `mslug.card` lands in OPFS after a
flush; after a reload the card is read back.

## Extension · 2026-11-14 — Walkthrough (implemented)

As planned:
- `scripts/web_bridge.cpp`: `web_set_dip(group, option)` (FBNeo's own DIP-menu write, offset from
  the `0xF0` entry), `web_memcard_insert()` (`/save/<driver>.card` or a blank card, inserted with
  `ACB_WRITE|ACB_MEMCARD|ACB_MEMCARD_ACTION`), and `web_persist()` writing the inserted card back
  (`ACB_READ|ACB_MEMCARD`, no eject). `build-fbneo.sh` exports both and `ccall` (string args).
- SDK: option `neogeo` (`mvs` default | `aes`), `neoGeoAesBios(entries)` (AES World by
  `neo-epo.bin` d27a71f1, else UniBIOS 4.0 a7aab458 + "Unibios mode" AES, else null), `#bootAes`
  after the set runs: settings → card → reset; `play.neogeo`. A set without the "BIOS" setting
  (not Neo Geo) is left alone; a Neo Geo without a usable BIOS fails `start()` with a message.
- App: forwards `host.options.neogeo`. README section "Neo Geo as the AES". Tests 21/21 (3 new).

**Verified** (Chromium, the wasm built here, the owner's `mslug.zip` + `neogeo.zip`): with
`neogeo: 'aes'` FBNeo loads the MVS BIOS, then after the reset `uni-bios_4_0.rom`; the screen reads
"THE UNIVERSE BIOS v4.0 · Region: EUROPE · Mode: CONSOLE", then the game; `play.neogeo` =
`{ mode: 'aes', bios: 'unibios', card: true }`; `mslug.card` (131072 bytes) in OPFS after a flush.
Without the option: MVS as before (`neogeo` null). No page errors.
**Not verified:** the real AES BIOS path (no `neo-epo.bin` here); a game writing to the card and
reading it back after a reload (mslug doesn't save to the card during the attract mode).

## Extension · 2026-11-14 — Titles in the ROM-set datasets; datasets regenerated at the pin

The launcher's Neo Geo library (play.germade#9) needs a set's name: the datasets only had
driver names (`mslug`). FBNeo's driver structs carry year, full name and maker right after the
short name, so `scripts/gen-romset-index.mjs` now emits them as `t`, `y`, `m` per game
(`RomsetGame` typed accordingly): `mslug` → "Metal Slug - Super Vehicle-001", 1996, Nazca.

Regenerating showed the checked-in `data/romsets/` came from a different FBNeo than the pinned
build (`d7179fef`): 259 sets' ROM lists differ, 229 sets are new and 3 are gone. Regenerated from the
pin, so the datasets describe exactly the drivers the wasm has (the app identifies sets with them).
All 25571 sets have a title. `make test` passes.

Commit: `feat(romsets): titles, years and makers in the datasets, regenerated at the FBNeo pin`
