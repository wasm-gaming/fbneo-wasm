# The keys bound to the pad's buttons work in the app's menus; engine-specs 0.6.2

## 2026-11-17 19:00 UTC — Plan

Report from the owner (play.germade, BlastEm first): in a pause menu the hints say "A" / "B" (the
pad), and on a keyboard the keys bound to the game's A and B did nothing: menus only took Enter /
Space and Escape / Backspace. Also, in fullscreen Escape left fullscreen instead of opening the
pause menu. engine-specs 0.6.2 fixes the second in `createFullscreenToggle()` and adds what the
first needs; BlastEm's app did it first (wasm-gaming/blastem-wasm#7), this is the same.

Plan:
- `@wasm-gaming/engine-specs` `^0.6.2`, lockfile updated (the build copies the runtime next to
  the SDK: Escape in fullscreen comes with it).
- `src/app/app.js`:
  - `menuControls()`: each of the engine's buttons with the player's key (saved, else default)
    and its **default** pad button;
  - `applyMenuKeys()`: `host.input.setKeyAliases?.(menuKeyAliases(menuControls()))` after each
    `play.setControls()` (boot, a rebind, reset); `setKeyAliases?.({})` on unmount (the input is
    the launcher's);
  - hints: a pad button gets its key next to it when it differs from the button's letter
    (`menuKeyHint()`).
- `src/app/app.css`: `.<prefix>-hints kbd.key`, an outlined key next to the filled pad button.
- Keys the menus already use (Enter, Space, Escape, Q, E, V, arrows) keep their meaning.

## 2026-11-17 20:50 UTC — Walkthrough and checks

- As planned: engine-specs `^0.6.2`; `menuControls()`, `applyMenuKeys()` after each

- `make test`: 27 / 27.
