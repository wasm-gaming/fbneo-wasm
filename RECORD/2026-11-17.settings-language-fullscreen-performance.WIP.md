## The common part (all the engines with a settings screen)

- **engine-specs `^0.4.0` → `^0.6.0`**. The app imports the helpers from `../engine-specs.js`, the
  runtime copy the Makefile already ships beside the SDK.
- **English and Spanish**:
  - every string of the app (today Spanish, inline) moves into one `{ en, es }` table;
  - the table is read through `host.locale ?? resolveLocale()`;
  - SDK errors stay English and are shown as a detail under the app's own words.
- **Pause menu**: Continuar, the engine's entries, **Ajustes**, **Pantalla completa**, Volver al
  lanzador (UX.md rule 4).
- **Ajustes**: `createSettingsScreen()`.
  - Rows come from `settingsModel()` over the SDK's `config()` / `options()` descriptors (only those
    with a `label`), plus `SHARED_SETTINGS`.
  - A live change is applied at once.
  - A non-live one is saved and passed at the next start; its row says "Se aplica al reiniciar".
  - Choices are saved per engine with `saveSettings('fbneo')` and read at mount with
    `loadSettings()`.
- **Fullscreen**: `createFullscreenToggle(root)` (Cmd+Enter / Alt+Enter, Select + Y), plus the
  pause-menu entry.
- **Performance**:
  - `createWakeLock()`, held while playing when "Mantener la pantalla encendida" is on (default
    on);
  - `createPerfCounter()` when "Mostrar rendimiento" is on: fed once per emulated frame where the
    SDK reports frames, else counting display frames.
- **Controls and audio pacing**: per engine, below.
- **Checks**:
  - `make test` / build;
  - in Chromium, with the owner's test ROMs where needed: the pause menu, every setting applied (or
    noted as on restart), saved across a reload, fullscreen by key and by menu, the counter, en / es;
  - a phone width.
- **Release**: minor.

## FBNeo

- **Settings**: `renderFilter` (CSS, live) → Vídeo "Suavizado". The player-1 controller
  (`gamepad` / `keyboard`) becomes a row in Controles, applied on restart.
- **Controls**: to check. FBNeo binds inputs inside the WASM (`fbneoArgs`, `-joy`). If its input
  config can be written before start, keys are remapped, applied on restart. If not, only the
  player-1 device choice is offered.
- **Audio pacing**: not offered (the loop runs inside the WASM).
- **Order**: fifth.

## Walkthrough (2026-11-17 23:40 UTC) — FBNeo done

Adds: what was built, what was settled from the plan's "to check" items, and the checks. It is
BlastEm's version of the template (blastem-wasm, same record), which is also SDL.

**Settled**:
- **Controls: yes, keys and pads, live**, by the same means as BlastEm (`src/fbneo.controls.ts`):
  - **keys**: a remapped physical key is replayed as FBNeo's default key for that control, and a
    freed default key is swallowed;
  - **pads**: the buttons are reordered in a wrapped `navigator.getGamepads()`;
  - the controls are fire 1–6, Coin, Start and the d-pad, with FBNeo's defaults (README):
    arrows, Z X C V, 5, 1; pad A B X Y LB RB, Select, Start;
  - fire 5 and 6 have no default key, so they are pad-only, and a key bound to them is ignored.
- **The player-1 device (pad or keyboard) is not a row.** The SDK picks it at start from whether a
  pad is connected (`-joy`), which is already the right choice. Remapping covers both.

**SDK**:
- `fbneo.controls.ts`: `FBNEO_CONTROLS`, `controlTables()`, `remapPad()`.
- `fbneo.sdk.ts`: `play.setControls()`, the key listener and the `getGamepads` wrapper.
- `fbneo.options.ts`: `renderFilter` → Vídeo "Suavizado", live.
- engine-specs `^0.4.0` → `^0.6.1`.

**App**: derived from BlastEm's finished app. FBNeo's own parts are kept and localized: the
driver identification (`identifyDriver`, `FIRST_SYSTEMS`), "Identificando el juego…", the two boot
errors, and "reset de la máquina".

**Checks**:
- `tsc` clean; `make test` 27 / 27, three of them new in `tests/controls.test.mjs` (the controls,
  key translation with the pad-only fire buttons, the pad reordering and a swap).
- In Chromium, with the published WASM: the app loads and shows its boot error in es and en
  ("No se pudo arrancar" / "Could not start").
- Not run in a browser: a game with the settings screen open. FBNeo needs a real ROM set (it checks
  every file's size and CRC, and the datasets carry no sizes, so one cannot be forged). The settings
  screen is the same code as BlastEm's, which was driven in Chromium.

## Fix (2026-11-18 00:30 UTC) — a remapped pad button does only what it was given

Found writing RSDKv4's test (same mechanism there). After binding a control to a button that was
not another control's default slot, that button still passed its own default meaning through. So
it pressed both the new control and whatever the engine reads there by default. `remapPad()` now
releases every button taken for a control unless it is itself a control's slot. Tests pass.
